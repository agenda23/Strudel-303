# 再改修計画書: Strudel × TB-303 アシッドテクノ作曲ツール

作成日: 2026-10-09 / 前版: `spec/改修計画書.md` / 基準: `spec/Strudel × TB-303 仕様・開発手順書.md`

## 0. 前版からの変更点

1. **録音機能は不要**: 前版 D-4（曲全体のWAV書き出し）を削除する。実装済みの録音（`src/app/recorder.ts`、REC ボタン）は撤去する。
2. **Strudel互換の機能・表示を調査対象に追加**: 「Strudelのコードがそのまま動くか」「Strudel標準の表示（再生位置・ピアノロール等）が使えるか」を §3 で調査し、§5 のフェーズGにまとめた。
3. 前版の実施結果レビュー（2026-10-09）で見つかった不具合を、フェーズBに追加した（§2）。

## 1. 現状の結論

改修済みの項目: 時間基準（`currentTime` 化）、ワークレット一本化（`?worker&url`）、パラメータ固着の解消、2.5msアタック、プリセットのBPM（`setcps`）、LICENSE/README。ビルドとテスト8件は通る。

ただし、次の理由でまだ「Strudelベースのアシッドテクノ作曲ツール」として使えない。

- スライドの修正が新しい不具合を生んでいる（休符越しのスライドで無音）。
- 303に delay / reverb / duck が掛からない（Orbitの出力合流点につないでいるだけ）。
- プリセットのドラムで、キックやクラップがハットのチョークに切られる。
- Strudel互換の観点（§3）で、**Strudelのコードを貼っても期待どおりに動かない箇所、Strudelらしい表示が無い箇所**が多い。
- 音の追い込み（フェーズE）、テストの網羅が未着手。

## 3. Strudel互換の調査結果

目的は「strudel.cc で書いたコードが、できるだけ同じ書き味で動き、Strudel標準の表示が使えること」。確認した事実と、未確認（実機確認が必要）の項目を分ける。

### 3.1 確認できた事実

| 項目 | 現状 |
| --- | --- |
| 依存 | `@strudel/web` 1.3.0（core / mini / tonal / transpiler / webaudio を再エクスポート）。`@strudel/draw` は `webaudio` の依存として入るが、アプリでは使っていない |
| エディタ | 素の CodeMirror 6（`basicSetup` + `javascript()` + `oneDark`）。`@strudel/codemirror` は未導入 |
| 画面の呼称 | 「Pattern Sequencer (Strudel REPL)」と表示するが、Strudel REPLの機能（ミニ表記ハイライト、`$:` ブロックごとの停止、`_pianoroll` のインライン表示、アクティブ音の強調）は無い |
| 303の経路 | `initStrudel({ defaultOutput })` の差し替えで `s("tb303")` だけ自前処理。`registerSound` は未使用なので、Strudelのサウンド一覧（`soundMap`）に `tb303` が現れない |
| 303が解釈する値 | `freq` / `note`（数値・音名）/ `n`（+`octave`）/ `legato` / `gain` / `velocity` / `accent` / `slide` / `tb*` のみ |
| 303が無視する標準コントロール | `clip` `sustain` `release` `attack` `pan` `orbit` `delay*` `room*` `lpf` `hpf` `postgain` `duck*` `cut` `shape` `crush` `coarse` ほか。**無視していることが利用者に伝わらない**（エラーも警告もなし） |
| BPM | プリセットは `setcps(bpm/60/4)`、BPMボタンは正規表現で `setcps(...)` を置換する方式。`.cpm()`、`setcpm()`、`cps` 指定のコードには効かない |
| 音源 | 909は `tidal-drum-machines.json` と `dirt-samples` をGitHubから取得（`samples()` が `main.ts` と `prebake` で二重呼び出し）。取得失敗の表示なし |
| 型 | `strudel.d.ts` は `any` 中心 |
| 保存 | `localStorage` に自動保存（実装済み） |

### 3.2 互換上の問題点

| ID | 問題 | 影響 |
| --- | --- | --- |
| S1 | `n("0 3 7").s("tb303")` は **サンプル番号ではなく半音オフセット**として扱い、オクターブ2固定。Strudelでは `n` + `scale` が `note` に変換される前提で、`scale` なしの `n` の意味が303だけ独自 | 貼り付けたコードの音程が想定とずれる。仕様を明示するか、`note` のみに統一 |
| S2 | `legato` の既定0.85、`clip` / `sustain` を見ない。Strudelでは音の長さの指定に `clip` / `legato` / `sustain` を使う | 長さの書き味が他の音と違う |
| S3 | `lpf` / `lpq` / `delay` / `room` / `pan` / `orbit` を黙って無視する | 303だけ効果が無く、原因が分からない |
| S4 | ミニ表記の位置ハイライト、再生中のステップ強調がない（`hap.context.locations` を使っていない） | 「Strudelらしい」表示がない |
| S5 | `.pianoroll()` / `.scope()` / `.spectrum()` / `.punchcard()` / `.spiral()` 等の標準可視化のサポートが未確認・未実装。独自のオシロ（303出力のみ）がある | 303の音がStrudelの可視化に出ない（`defaultOutput` 差し替えでは `hap.context` の描画連携が通らない可能性）。要実機確認 |
| S6 | `$:` ブロックごとの mute（`_$:`）、`all()`、`.p("name")`、`hush` / `silence` の動作が未確認。停止時に303のキューをリセットするが、ブロック単位では止まらない可能性 | ライブ操作の互換性 |
| S7 | 画面右の「Synthesis Parameters」「LED」等の独自表示は、パターン側が値を持たない（デフォルト値）場合に `--` のまま、または古い値を残す | 表示が実際の音とずれる |
| S8 | 303固有コントロールの名前（`accent` `slide` `tb*`）が `.d.ts` / オートコンプリート / マニュアルの3か所に散在。Strudel側の `registerControl` の別名(`dec` 等)と揃っていない | 保守しにくい。書き味の一貫性がない |
| S9 | 内部API依存: `defaultOutput` の引数、`hap.ensureObjectValue`、`hap.hasOnset`、`hap.context.onTrigger`。バージョン固定と互換テストがない | Strudel更新で壊れうる |
| S10 | 動作確認の基準になる「strudel.cc 互換スニペット集」がない | 互換の判定ができない |

### 3.3 未確認（フェーズAで実機確認）

- `defaultOutput` 差し替え方式で、`hap.context` が `@strudel/draw` の描画やハイライトに渡るか。
- `registerSound` で単音常駐のワークレットを使う場合の、`onTrigger(t, value, onended)` の寿命管理（`onended` の扱い、ノード返却の要否）。
- `all()` / `.p()` / `_$:` が `evaluate` 経由で動くか（`@strudel/transpiler` の対応）。
- `@strudel/codemirror` を組み込めるか（バンドルサイズ、依存の整合、AGPL）。

## 4. 改修方針

1. DSPコア・ワークレットは現行の一本化を維持し、実際に鳴る経路をテストする。
2. 303は `registerSound('tb303', …)` でsuperdoughに登録し、他の音と同じ経路（エフェクト、オービット、サウンド一覧）に載せる。独自の `defaultOutput` 差し替えは撤去する。
3. Strudel標準のコントロール名・意味を優先し、303固有は `tb*` に限定する。未対応のコントロールは警告を出す。
4. 表示はStrudel標準（ハイライト、`pianoroll`/`scope` 等）を使い、独自表示は最小限にする。
5. 録音・書き出しは作らない。実装済みの録音は撤去する。
6. 仕様外機能（AI、MCP）は安全性を直した上で既定オフにする。

## 7. リスクと未確認事項

- `registerSound` で単音常駐のワークレットを使えるかは A-1 の結果次第。不可なら、`defaultOutput` 差し替えを維持し、303出力を `getOrbit` の入力経路（エフェクトの送り先）へ接続する代替案を取る。
- `@strudel/codemirror` の導入可否（依存、サイズ）が不明。不可なら G-1 は `hap.context.locations` を用いた自前ハイライトにする。
- 描画（`pianoroll` 等）は `hap.context` の内容に依存する。独自経路では動かない可能性がある（G-2 の前提は A-1）。
- 「303らしさ」の合否は聴き比べであり、数値だけでは決まらない。参照音の入手方法を先に決める。
