# Strudel × TB-303 仕様・開発手順書

Oct 8, 2026 · @Masataka Koguchi

## 概要とゴール

Strudel風のコード入力UIで909・303・ブレイクビーツを打ち込めるブラウザアプリを作る。ドラムとブレイクはStrudel既存機能に任せ、新規開発は303ボイス（AudioWorklet）とその制御パラメータに絞る。

成功の定義:

- パターンコードだけで、909ドラム・303ベースライン・ブレイクビーツのループが同期して鳴る
- 303がフィルタースイープ・アクセント・スライドで「303らしく」聴こえる。実機または参照実装との聴き比べで、違いが小さいことを目標にする
- 303ボイス1つの再生中、`process()` 1回あたりの処理時間がブロック時間（128サンプル ≒ 2.9ms @44.1kHz）の10%以下（案）
- 静的サイトとして公開できる

## スコープ

303ボイスの自作とStrudelへの接続に集中し、909・ブレイク・パターン言語・UIの基盤は既存のものを使う。

| 項目 | 方針 | 理由 |
| --- | --- | --- |
| 303ボイス（VCO/VCF/MEG/VEG/アクセント/スライド） | **作る** | Strudel標準にない。再現度の大半を決める部分 |
| 303用パターンパラメータ（accent, slide など） | **作る** | Strudelにタイ/スライドの概念がない |
| 909ドラム | 既存を使う | ドラムマシンのサンプルバンクで足りる |
| ブレイクビーツ | 既存を使う | `chop` `slice` `splice` `loopAt` で足りる |
| パターン言語・スケジューラ | 既存を使う | `@strudel/web` に含まれる |
| エディタUI | 簡易版を作る | CodeMirrorでREPL風にする |
| 実機の回路シミュレーション（WDF等） | やらない（将来検討） | 実装コスト大。TPT＋tanhで足りるか先に確認する |
| DAWプラグイン化 | やらない（将来検討） | DSPコアを純TSで分離しておけば後で移植できる |
| 303以外のシンセ・ポリフォニー | やらない | スコープ外 |

## 303 DSP仕様

「303らしさ」の大半はフィルタ、エンベロープ、アクセントとスライドの挙動で決まる。VCOはエイリアシング対策さえ入れれば単純でよい。数値は初期値（仮）で、フェーズ5で実機比較をして詰める。

| ブロック | 仕様 | 初期実装 |
| --- | --- | --- |
| VCO | ノコギリ波／矩形波の切替。1オクターブ上下のオクターブ指定に対応 | PolyBLEPでエイリアシングを抑える |
| VCF | 4ポール・ダイオードラダー型ローパス。レゾナンスは出力から入力への負帰還。段ごとに非線形飽和を持つ | TPT離散化＋段間tanh、2〜4倍オーバーサンプリング。tanhは近似関数で置換可能な構造にする |
| MEG（フィルタ用EG） | ノート開始で即立ち上がり、指数的に減衰。減衰時間はdecayで可変。envmodでカットオフに加える量を決める | 1次の指数エンベロープ |
| VEG（アンプ用EG） | ゲートONで立ち上がり、ゲートOFFで短いリリース。スライド中は再トリガーしない | ゲート信号＋指数カーブ |
| アクセント | アクセントのノートはMEGの効きとVCAレベルが増す。アクセント回路の電荷が連続アクセントで蓄積し、続くほど効きが強くなる（アクセントスイープ） | 蓄積用の状態変数を1つ持ち、アクセント時に加算、時間とともに放電。時定数は実機録音から決める |
| スライド | ピッチが一定時間で次のノートへ移る。ゲートは切れず、MEG・VEGは再トリガーされない | 時間一定のポルタメント。初期値は60ms前後（仮）。線形か指数かは実機録音と比べて決める |
| パラメータ平滑化 | cutoff・resなどの急変でクリックを出さない | 数ms程度の1次スルー |

実機のスライドは、そのステップのスライド指定が「次のステップへの移行」に掛かる動きと理解している。この点は実機の挙動を確認してから確定する。

DSPコアは Web Audio に依存しない純TypeScriptのクラスとして書く。これでNode上のテストとWAV書き出しができ、将来のDAWプラグイン化やWASM化にも移植しやすい。初期はJSのままで足り、CPUが目標に届かない場合だけWASM化を検討する。

## パターンAPI仕様

303は `s("tb303")` で呼び、音程は既存の `n` / `note` を使う。303専用のパラメータは、Strudel既存のフィルタ系コントロール（`lpf` `lpq` `decay` など）と名前が衝突しないよう `tb` 接頭辞で足す。名前は仮で、フェーズ0で衝突の有無を確認して確定する。

| パラメータ | 値 | 意味 |
| --- | --- | --- |
| `accent` | 0 / 1 | そのステップをアクセントにする |
| `slide` | 0 / 1 | そのステップから次のステップへスライドする |
| `tbcut` | Hz（目安 50〜8000） | フィルターのカットオフ基準値 |
| `tbres` | 0〜1 | レゾナンス |
| `tbenv` | 0〜1 | MEGがカットオフを動かす量（Env Mod） |
| `tbdec` | 秒（目安 0.2〜2） | MEGのディケイ |
| `tbwave` | `saw` / `square` | 波形 |
| `tbslidetime` | 秒（初期 0.06） | スライド時間 |

動作ルール:

1. 同時に鳴らせるのは1音だけ。ノートが重なったら後のものを優先する
2. ゲート長はStrudelのイベント長を使う（`legato` `clip` で調整）
3. 前のノートが `slide=1` で、次のノート開始時にゲートが続いていれば、ピッチだけ動かしてMEG・VEGは再トリガーしない
4. アクセントの蓄積状態はボイスが保持し、パターン側からは見えない

書き味のイメージ（909・ブレイクと並べる例）:

```js
$: n("0 0 12 7 ~ 3 5 0").scale("c2:minor")
  .s("tb303")
  .accent("0 1 0 0 0 1 0 0")
  .slide("0 0 1 0 0 0 1 0")
  .tbcut(sine.range(300, 3000).slow(4))
  .tbres(0.8).tbenv(0.6).tbdec(0.2)

$: s("bd*4, ~ cp ~ cp, hh*8").bank("RolandTR909")

$: s("amen").chop(8).loopAt(2)
```

## 実装方針

Strudel本体は改造せず、`@strudel/web` を依存として使い、自作の303ワークレットを外側から接続する。本体のアップデートに追従しやすくするためである。

| 項目 | 選択 |
| --- | --- |
| ビルド | Vite + TypeScript |
| パターン／音声エンジン | `@strudel/web`（`initStrudel` で初期化） |
| エディタ | CodeMirror 6（評価・停止のショートカット付き） |
| 303のDSP | 純TSのコア＋AudioWorkletのラッパー |
| ホスティング | 静的サイト（Cloudflare Pages など） |

**ファイル構成（案）**

```text
src/
  dsp/            # Web Audio非依存の純TS（テスト・WAV出力可）
    tb303.ts      #   ボイス本体（VCO/VCF/EG/アクセント/スライド）
    ladder.ts     #   ダイオードラダー
    polyblep.ts
  worklet/
    tb303.worklet.ts   # dsp/ を呼ぶAudioWorkletProcessor、イベントキュー
  strudel/
    bridge.ts     # Strudelのイベントを303ワークレットへ送る
    controls.ts   # accent, slide, tb* の登録
  app/            # CodeMirror UI、再生・停止
tools/
  render.ts       # dsp/ を使ってNode上でWAVを書き出す
```

**Strudelとの接続は2段階で進める。**

1. 最小の接続: パターンの `.onTrigger()` で、イベントごとに自前のワークレットへメッセージを送り、出力は `AudioContext` へ直接つなぐ。Strudelの内部に深く触れずに済む
2. 本格的な接続: superdoughに `tb303` をサウンドとして登録し、Strudel標準のオービット（delay・reverbなど）に載せる

**ワークレットの動かし方。** 303は単音で状態を持つため、イベントごとにノードを作らず、1つの常駐ノードを使う。ブリッジが、開始時刻（`AudioContext` 時間）・周波数・ゲート長・accent・slide・パラメータをポートで送る。ワークレットは時刻をフレーム位置に直し、サンプル精度で発音する。送信は先読み区間内に収まる必要がある。

上記のStrudel内部のAPI名と引数（`onTrigger` の第2引数の意味、サウンド登録関数、カスタムコントロールの登録方法）は記憶に基づくため、フェーズ0でソースを読んで確認する。

## 開発手順

音を決めるDSPコアを先に単体で完成させ、その後にブラウザ・Strudel・UIを順に重ねる。各フェーズは完了条件を満たしてから次へ進む。

| フェーズ | 作業 | 完了条件 |
| --- | --- | --- |
| 0. 調査・準備 | Strudelのリポジトリを読み、サウンド登録・ワークレット読み込み・`onTrigger`・カスタムコントロールの仕様を確認する。既存のラダー系フィルタ（`ftype` など）の有無を確認する。比較用の参照音（実機録音、または参照実装のレンダリング）を用意する | 「リスクと未確認事項」の確認項目がすべて解消している。参照音が手元にある |
| 1. DSPコア（純TS） | PolyBLEPのVCO、ダイオードラダー、MEG/VEG、アクセント、スライドを `dsp/` に実装する。`tools/render.ts` で固定シーケンスをWAVに書き出す | 固定シーケンスのWAVが出力でき、聴いて303系の音と分かる。エイリアシングの確認（下記）を通る |
| 2. AudioWorklet化 | ワークレットのラッパー、イベントキュー、最小のテストページ（ボタンで鳴らす）を作る | ブラウザで連続再生でき、クリックノイズがない。CPUが目標内（概要参照） |
| 3. Strudel接続 | `@strudel/web` を初期化し、`.onTrigger()` 方式でaccent・slide・`tb*` を接続する。909とブレイクを並べて鳴らす | 例のパターンで303・909・ブレイクが同期して鳴り、accentとslideが聴き分けられる |
| 4. エディタUI | CodeMirror 6で入力欄を作り、評価・停止のショートカットを付ける。エラー表示を出す | コードを書き換えて評価すると、再生が切れずに切り替わる |
| 5. 音の追い込み | 参照音とスペクトル・エンベロープ形状を並べて比較し、定数（スライド時間、アクセント時定数、レゾナンスの効き、ゲイン）を調整する。プリセットを作る | 参照音との聴き比べで差が小さいと判断できる。調整後の定数が記録されている |
| 6. 公開・拡張 | 静的ホスティングへデプロイする。`registerSound` 方式への移行（オービット対応）、WASM化、MIDI入力、Tauri化は必要に応じて行う | 公開URLで動作する。ライセンス対応（リスク参照）が済んでいる |

## 検証・品質基準

音の再現度は耳と波形の両方で確認する。数値の基準は案で、フェーズ1〜2で実測してから確定する。

| 観点 | 方法 | 合格基準（案） |
| --- | --- | --- |
| 音色の再現 | 同じシーケンスを参照音と同条件で鳴らし、スペクトログラム、カットオフスイープ時のスペクトル、MEGの減衰形状を並べる | 聴き比べで差が小さい。スイープの形と減衰の形が重なる |
| エイリアシング | 高音域のノコギリ波と高レゾナンスを鳴らし、スペクトルを見る。オーバーサンプリングの有無でも比べる | 倍音列に乗らない折り返し成分が目立たない |
| 安定性 | カットオフ・レゾナンスを全範囲で振り、最大レゾナンスでも発振して発散しないことを確認する | 出力が常に有限で、NaNが出ない |
| CPU | `process()` の処理時間を計測する | ブロック時間の10%以下 |
| タイミング | 10分以上の連続再生で、発音漏れ・遅れを数える | 発音漏れがない |
| クリック | パラメータ急変、ループの境目、ノート切り替えで波形の不連続を確認する | 耳に付くクリックがない |
| 回帰テスト | `dsp/` が出す固定シーケンスのWAVを基準と比較する自動テスト（vitest） | 定数を変えない限り出力が一致する |

## リスクと未確認事項

最大のリスクは、Strudelの内部APIとライセンスが記憶に基づく点である。フェーズ0で下の項目をすべて確認してから実装に入る。

| 項目 | 内容 | 対応 |
| --- | --- | --- |
| ライセンス | StrudelはAGPL-3.0と記憶している。依存して公開する場合、ソース公開などの条件が掛かる可能性がある | フェーズ0でLICENSEを確認する。公開する場合はソースも公開する前提で進める |
| 内部API | サウンド登録、ワークレット読み込み、`onTrigger` の第2引数、カスタムコントロール登録は記憶ベース | リポジトリのソースを読み、最小の動作例で確かめる |
| 既存のラダーフィルタ | 最近のStrudelにラダー系フィルタが入ったと記憶しているが未確認 | あれば音を聴いて比較し、自作の必要性を判断する |
| フィルタの二重掛け | `registerSound` 方式では、superdoughが標準のフィルタを出力にも掛ける可能性がある | `tb` 接頭辞のコントロールを使い、標準の `lpf` などを併用しない |
| イベントの到着遅れ | メッセージが先読み区間に間に合わないと発音が遅れる・漏れる | 先読み時間を調整する。それでも足りなければSharedArrayBufferを検討する（COOP/COEPヘッダーが必要） |
| strudel.cc上では使えない | 自作ワークレットを公式サイトのREPLに読み込む経路がない | 自前ページで動かす（本書の前提） |
| 実機の仕様 | スライドの掛かり方、アクセントの時定数、スライド曲線は未確定 | 実機録音または参照実装と比べて確定する |
| 参照実装のライセンス | Open303などを参考にする場合、ライセンスが異なる | 挙動の理解に使い、コードは写さない。使う前にライセンスを確認する |
| 参照音の権利 | 他人の録音を比較以外に流用できない | 自分で録音した音、または権利上問題のない音を使う |
