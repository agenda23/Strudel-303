# MCP 経由の楽曲検証と TB-303 クローン評価・改修計画

実施日: 2026-10-10 / 対象: Strudel 303 (main) / 方法: MCP サーバー（`mcp/server.ts`）を MCP クライアントから起動し、5 ツールを呼んで生成・再生・レンダリングし、Chrome 上のアプリ（`localhost:3000/?mcp=1`）の出力を測定。DSP は `tools/analyze303.ts`（新規）でオフライン測定。

## 1. 結論

- **MCP 連携は動作する**（5 ツールとも応答、`play_live_pattern` でブラウザが再生、AGENT READY）。ただし、AI が結果を検証できる仕組みが無い（§4）。
- **楽曲は構成の修正で大きく改善できた**（音程・ミックス・アレンジ）。ただし、その原因の一部は**アプリ側の生成テンプレートとドキュメントの誤り**で、改修が必要（§3）。
- **TB-303 クローンとしては「それらしく鳴る」段階**。スライド・アクセント蓄積・タイミング同期は良好。一方、フィルタ特性（24dB/oct、レゾナンスの質）、歪みの音量跳ね、オシレーターのエイリアシングなど、**音の追い込みで直すべき点がある**（§2）。

## 2. TB-303 クローンとしての評価

### 良好（実測）
| 項目 | 結果 |
| --- | --- |
| 同期 | 303 の発音要求は先読み 110〜347ms（平均 294ms）で全件間に合い、遅れ 0 件。ステップ間隔は 138 BPM の 16 分で 0.1087s と一定（83 発音） |
| スライド | ピッチ到達 95% が 60ms、指数カーブ。MEG/VEG は再トリガーされない |
| アクセント | 通常比 約 +4dB（ピーク 0.26→0.42）。連続アクセントで 0.42→0.49 まで蓄積し、4 発程度で飽和（アクセントスイープの模擬として成立） |
| MEG | cutoff 300Hz・envmod 1.0 で 4078Hz から指数減衰（0.1s で 1731Hz、0.3s で 738Hz） |
| 安定性 | 全範囲で NaN なし。レゾナンス最大でも発散しない |

### 303 らしさの不足（アプリ側の課題）
| ID | 内容 | 実測 |
| --- | --- | --- |
| D1 | **フィルタが 24dB/oct**。実機のダイオードラダーは約 18dB/oct の応答で、4 ポール均一段のムーグ型に近い | res 0 で 2k→8k が −23.1dB/oct |
| D2 | **レゾナンスの質**。ピークは res=1.0 で +13dB、res=0.8 で約 0dB。インパルス応答は 1.5s 後に 1e-18 まで減衰し、自励発振に近い持続はない。低域は res 0.5 で −9dB、1.0 で −13.5dB 落ちる | 実機の「スクイール」より控えめで、低域の痩せが大きい |
| D3 | **歪みユニットの音量跳ね**。drive を 0 → 0.25 にしただけで RMS が 0.091 → 0.358（約 +12dB）、ピーク 0.37 → 1.38 | `tbdist` を使うプリセット・生成曲がマスターでクリップする |
| D4 | **オシレーターのエイリアシング**（フィルタ前）。非高調波成分が 110Hz で −40dB、523Hz で −34dB、1.3kHz で −30dB、2kHz で −28dB | PolyBLEP としては目標（−55dB 以下）に届かない。フィルタが開いたハイノートで耳につく可能性。要聴感確認 |
| D5 | **303 の既定出力が小さい**。単体ピーク 0.37 / RMS 0.09 に対し、909 キックは 0.80 / 0.20（約 −9dB 差）。superdough の既定 gain 0.8 に加え、DSP 内の 0.7 係数が重なる | 既定のままドラムと並べると 303 が埋もれ、`gain` を上げると歪みで急に破綻する（D3） |
| D6 | **アクセント時のディケイ**は一律 ×0.7。実機はアクセントでディケイが短い固定値になり、レゾナンスの効きも増す | 近似止まり |
| D7 | **波形**: 矩形波は単純 50% パルス。実機の矩形波は鋸波をシェイプしたもので、非対称 | 聴き比べ未実施 |
| D8 | マスターに**リミッター／ヘッドルーム管理がない**。909 + 303 が重なるとクリップ（`classic` 生成曲で確認: ピーク 1.56。他のスタイルは未測定） | `bd` 単体 0.8 / `hh*16` 0.79 / `cp` 0.83 と、909 サンプル自体が大きい |

> 注: D4 の数値はフィルタ前のオシレーター単体。D1〜D3 は DSP 単体の実測、D5・D8 はブラウザのマスター出力の実測。

## 3. 楽曲の検証と調整

### 3.1 問題と原因の切り分け
| 問題 | 原因 | 修正の場所 |
| --- | --- | --- |
| **音程が意図とずれる**: 生成曲は `n("0 0 12 7 ~ 3 5 0 …").scale("c2:minor")`。`12` は「半音 12 = 1 オクターブ」のつもりだが、`scale()` の下では **12 度上**（C2 → Ab3 まで届く）。実測の音列は C2 C2 **Ab3** C3 … と広い跳躍になる | テンプレートと説明が半音の感覚で書かれている（アプリ側の誤り） | **アプリ（生成テンプレート・プリセット・AI プロンプト・マニュアル）**。曲側の修正だけでは再発 |
| **クリップ**: 生成曲は bd + cp + hh*16 が 1 つの `$:` で全部最大音量、303 は歪み有りで +12dB。ピーク 1.56・5 秒で 363 サンプルがクリップ | 生成曲のゲイン設計の不在（曲）＋ D3/D8（アプリ） | 曲（ゲイン調整）＋アプリ（D3, D8） |
| **アレンジが単調**: 16 ステップ 1 パターンを永久ループ、ハイハットは `hh*16` で一定、オープンハット・コンプなし、303 の入り・抜きがない | 生成器が固定テンプレート | 曲（すぐ可能）＋アプリ（生成器の改善） |

### 3.2 調整した曲
`docs/examples/acid-techno-138.js`（138 BPM、8 小節ループ）。MCP の `tb303_play_live_pattern` で再生し、ブラウザの出力を測定して調整した。
- 音列を **スケール度数**で書き直し（`7` = オクターブ、`0 0 7 4 ~ 2 3 0 …`）、2 小節ごとに変化（`<a b>`）。
- 303 は 3 小節目から入る（`.mask("<0 0 1 1 1 1 1 1>")`）。アクセント／スライドも 2 バリエーション。
- ドラムを分離: キック、クラップ（2 小節目から）、オープンハット（`cut(1)`）、クローズドハット（3 小節目から、ゲインを揺らす）。
- ゲイン: 303 `0.2`、キック `0.7` ほか。歪み `tbdist(0.25)` を使う場合は D3 のため **303 の gain を 0.2 まで下げる必要**がある（`1.0` ではピーク 1.38）。

| 調整段階 | ピーク | クリップ（1 小節あたり） |
| --- | --- | --- |
| 生成曲そのまま（classic） | 1.56 | 363 サンプル / 5 秒 |
| 初版（303 gain 1.5 + 歪み） | 2.4〜2.9 | 約 1 万サンプル |
| gain 0.45 | 1.1〜1.6 | 数十〜数百 |
| gain 0.28 | 1.0〜1.2 | 2〜17 |
| **gain 0.2（最終）** | **0.7〜1.2** | **0〜11（多くは 5 以下）** |

**限界**: ゲイン調整だけでは、キック・303 のアクセント・クラップが重なる瞬間に残る数サンプルのクリップを消せない（ピーク最大 1.2）。マスターリミッターが必要（D8）。曲を **クリップ 0** にするには、さらにドラムを下げる必要があり、その場合は 303 とのバランスが崩れる。**よって曲側の修正は限界に達しており、残りはアプリ側の改修**。

## 4. MCP / AI エージェント連携の課題

| ID | 内容 | 確認結果 |
| --- | --- | --- |
| M1 | **評価エラーが返らない**。構文エラーや未定義メソッド（`.nonexistent(3)`）を送っても、ツールは「Successfully broadcasted … playback started」を返す。ブラウザ側もエラーバナーを出さず、ステータスは RUNNING のまま（Strudel の `evaluate` が例外を握りつぶすため） | AI が失敗に気づけない。UI でも手入力のエラーが見えない |
| M2 | **状態を読み戻せない**。現在のコード、再生状態、音量（ピーク／クリップ）、エラーを取得するツールがない | AI が自分の曲を検証できず、今回の測定は Chrome を別途操作する必要があった |
| M3 | **オフライン検証が弱い**。`tb303_render_audio_file` は固定の 16 ステップ（303 単体）を鳴らすだけで、現在のパターンやドラムは反映されない | WAV 回帰・AI の自己検証に使えない |
| M4 | **複数ブラウザへの一斉配信**。接続中の全タブに送られ（今回も 2 窓）、別タブの音が鳴る | 運用上の注意。ターゲット指定が欲しい |
| M5 | ポート 3031 を前の MCP サーバーが握ったままになる（クライアント切断後もプロセスが残るケース） | 2 つ目のサーバーは黙って WS を立てられず、再生ツールが「ブラウザ未接続」になる。起動時に明示的にエラーにすべき |
| M6 | 生成器（`tb303_generate_pattern`）の曲が §3.1 の問題を含む | §5 で改修 |

## 6. 検証方法（再現手順）
- DSP: `npx tsx tools/analyze303.ts`（フィルタ応答、共振、エイリアシング、アクセント、スライド、MEG、リリースを出力）。
- 曲: アプリを `?mcp=1` で開き、MCP クライアントから `tb303_play_live_pattern` で再生。ブラウザ側で `getSuperdoughAudioController().output.destinationGain` に AnalyserNode をつなぎ、ピーク・RMS・クリップ数を測る（K-2 で自動化予定）。
- 同期: `soundMap` の `tb303` の `onTrigger` をラップし、`t − audioContext.currentTime` を記録。

- 測定は 1 台のブラウザ（Windows の Chrome）、1 セッション。
- 測定中、別タブ（ユーザー側の `?mcp=1` タブ）にも一時的に再生コードが配信された（M4）。

## 13. つまみの連続操作（ノブレーン、2026-10-10）

**指摘**: 303 らしさには、演奏中のつまみ操作による連続的な音色変化が含まれる。カットオフやレゾナンスを通常のシーケンスで打ち込むと階段状になる。

**確認（実測）**: `note("c2*16").s("tb303").tbcut(sine.range(300,2400).slow(2))` は 1 サイクルに 16 個の値（隣接で最大約 200Hz の段差）。ノートごとにしか値が反映されず、長いノートの途中やスライド中は動かない（修正前）。

| 項目 | 内容 |
| --- | --- |
| 仕組み | `s("tb303ctl").segment(N).tbcut(<信号>)...` のイベントを「ノブの目標値」として扱い、ワークレット内で**サンプル単位にランプ**（カットオフは対数、他は線形）。ランプ長は 1 制御点の長さ。`registerSound('tb303ctl')` は音を出さずメッセージ（`knobs`）を送る |
| 動かせる対象 | `tbcut` `tbres` `tbenv` `tbdec` `tbdrive` `tbdist` `tbdisttone`（`KnobKey`） |
| 優先順位 | レーンが動かしているパラメータは、ノートが明示しない限りレーンの値を保つ。ノートが明示した場合はその頭で優先され、ランプは中断。評価し直しで解除（`clearKnobs`） |
| 共通化 | ボイスへの命令（`note` / `knobs` / `clearKnobs`）を `src/dsp/events.ts` に集約し、AudioWorklet とオフラインレンダラー（`tb303_render_current`）が同じ処理を共有。レンダラーもレーンに対応 |
| テスト | `tests/knobs.test.ts`（6 件）: ランプの連続性（対数中点、1 サンプルあたりの比 < 1.0025）、レーンの保持と明示値の優先、解除、`segment(128)` はノート単位より 6 倍以上滑らか、レーン有りのレンダリングで高域が開くこと・クリックなし。全 106 件成功 |
