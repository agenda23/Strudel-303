## T1: B3 (時間基準のずれ) の調査結果

### 1. 現状の現象と原因
- `src/worklet/tb303.worklet.ts` (および `processor-code.ts`) では以下のようにスケジューリングされている:
  ```typescript
  const targetFrame = Math.max(this.frameCounter, Math.round(data.time * sampleRate));
  ```
- ここで `this.frameCounter` はプロセッサ内部で `0` から開始するローカル変数である。
- 一方、`data.time` は Strudel のスケジューラが渡す `AudioContext.currentTime` 基準の絶対時刻 (秒) である。
- `AudioContext` はページロード後即座に開始され、再生開始時には数秒〜数分進んでいる（例: `currentTime = 5.2s`）。
- この場合、`data.time * sampleRate = 5.2 * 44100 = 229,320` となるが、新しく作られた WorkletNode の `this.frameCounter` は `0` であり、229,320 フレーム経過するまでイベントが発音されないか、あるいは `time` の基準が狂って 909 ドラム（superdough 側は `AudioContext.currentTime` で即時スケジューリング）と決定的にタイミングが乖離する。

### 2. 修正方針 (B-1)
- `AudioWorkletGlobalScope` には標準プロパティ `currentFrame` (int64) および `currentTime` (float64) が存在する。
- または、各ブロックの処理開始時点で `currentBlockTime = currentTime`（秒）とし、サンプルごとに時刻 `sampleTime = currentBlockTime + i / sampleRate` を算出して `data.time <= sampleTime` でイベントを発火する。
- これにより、ノード生成時期に関わらず `AudioContext.currentTime` と完全同期し、タイミングのズレは 1 サンプル精度（<= 0.02ms）となる。

## T2: B1 / B2 (スライド意味論と legato) の再現結果

### 1. ユニットテストでの失敗確認
- `tests/slide_semantics.test.ts` を作成し、現行コードに対してテストを実行。2件とも **FAIL (赤)** を確認。

### 2. B1 (スライド不発) の原因
- `src/strudel/bridge.ts` では、ノートのゲート長がデフォルトで以下のように計算される:
  ```typescript
  const legato = typeof val.legato === 'number' ? val.legato : 0.85;
  const gateDuration = Math.max(0.01, durationSec * legato);
  ```
- ステップの 85% でゲートが閉じるため、次のステップの onset (開始時刻) に達した時点では `this.gate = false` になっている。
- `src/dsp/tb303.ts` の `triggerNote` では `if (slide && this.gate)` と判定しているため、`this.gate` が false の状態ではスライド条件が成立せず、常にエンベロープがリトリガーされてしまう。

### 3. B2 (スライド意味論の反転) の原因
- 仕様書 ルール3: 「そのステップから**次**のステップへスライドする（前のノートが `slide=1`）」。
- 実装: 現在のノートの `val.slide` を見ており、「前のノートからこのノートへ滑り込む」仕様になっており、1拍ずれる。

### 4. 修正方針 (B-2)
- `bridge.ts` において、前のノートの `slide` フラグを保持する (`previousSlide`)。
- 前のノートが `slide=1` の場合:
  1. 前のノートのゲート長を次のノートの開始時刻までタイ（100% またはそれ以上）として延長する。
  2. 次のノートが到着した際、`isSlideToThisNote = previousSlide` としてワークレットに渡す。
  3. `TB303Voice` 側では、スライド遷移時はエンベロープ（MEG/VEG）を再トリガーせず、ピッチのみをポルタメント（`slideTime`）で移行する。

## T3: superdough / registerSound 仕様確認とライセンス

### 1. superdough の音源登録 (`registerSound`) の仕様
- `superdough.mjs` の `registerSound(key, onTrigger, data)`:
  - `onTrigger(t, value, onended)` は各ノートトリガー時に呼ばれ、AudioNode（または `{ node, stop }`）を返す。
  - 返されたノードは superdough の `Orbit`（delay, reverb, gain, pan, duck）へルーティングされる。
- **課題**: TB-303 はモノフォニックかつアナログ回路の内部状態（コンデンサ電荷、フィルタ状態、ポルタメント状態）を維持するため、**単一の常駐 WorkletNode** で処理する必要がある。
- **解決策**:
  - `defaultOutput` のインターセプト方式、あるいは常駐 WorkletNode の出力を superdough の Orbit summing ノードまたは `AudioContext` エフェクトチェーンに接続する。
  - これにより、単音常駐の音響的一貫性とオービットエフェクト（delay/reverb/gain）の両立を図る。
